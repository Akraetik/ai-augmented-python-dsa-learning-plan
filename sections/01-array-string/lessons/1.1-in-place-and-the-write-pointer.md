# 1.1 · In-Place Edits and the Write Pointer

**Labs:** 01 Merge Sorted Array · 02 Remove Element · 03 Remove Duplicates · 04 Remove Duplicates II
**Time:** 60 minutes reading and tracing, then the labs.

---

## The problem family

Four of the first problems in this section share one shape:

> Change the list you were given. Don't build a new one. Then report how many items are "kept."

That last part matters. LeetCode checks the first `k` items of your list, where `k` is the number you return.
What's after position `k` doesn't matter. Leave junk there. Nobody looks.

## The idea: two pointers going the same way

You use two indexes.

- **`read`** walks every item, start to finish. It looks.
- **`write`** marks the next slot to fill with a "kept" item. It only moves when you keep something.

`read` is always at or ahead of `write`. So you never overwrite something you haven't read yet.

```
keep items that are not 0

 nums:  [3, 0, 5, 0, 7]
         w
         r          read 3 → keep → nums[w] = 3, w = 1

 nums:  [3, 0, 5, 0, 7]
            w
            r       read 0 → skip

 nums:  [3, 0, 5, 0, 7]
            w  r    read 5 → keep → nums[w] = 5, w = 2

 nums:  [3, 5, 5, 0, 7]
               w  r read 0 → skip

 nums:  [3, 5, 5, 0, 7]
               w     r read 7 → keep → nums[w] = 7, w = 3

 nums:  [3, 5, 7, 0, 7]   return 3. First 3 slots: [3, 5, 7]. Done.
```

## Worked example: keep only the even numbers

Not one of the labs. Same pattern. Study it, then trace it.

```python
def keep_evens(nums: list[int]) -> int:
    write = 0
    for read in range(len(nums)):
        if nums[read] % 2 == 0:          # the "keep" rule
            nums[write] = nums[read]
            write += 1                    # M4: save it
    return write                          # how many we kept
```

Three parts. Only the **keep rule** changes from problem to problem.

1. `write = 0`
2. For each item: if it passes the keep rule, copy it to `write` and move `write`.
3. Return `write`.

Time O(n). Space O(1).

### Trace it

Trace `keep_evens([4, 1, 6, 6, 3])` on paper. What's returned? What are the first `k` items?

<details><summary>Answer</summary>

Returns 3. First 3 items: `[4, 6, 6]`. Full list: `[4, 6, 6, 6, 3]` (the tail is leftover junk).
</details>

## The keep rule changes. The skeleton doesn't.

| Problem | Keep rule |
|---|---|
| Remove Element (lab 02) | the item isn't the value to remove |
| Remove Duplicates (lab 03) | the item is different from the **last kept** item |
| Remove Duplicates II (lab 04) | allow each value **twice** — compare with the item two kept slots back |

For the duplicates problems, the list is **sorted**. That's the clue. Sorted means duplicates sit next to each
other. So "is this new?" only needs to look back at what you already kept.

Here's the key question for lab 03. Say it to yourself before you code:

> "Do I compare `nums[read]` with `nums[read - 1]`, or with `nums[write - 1]`?"

Both can work for lab 03. Only one generalizes to lab 04. Figure out which, and why.

## A different direction: fill from the back

Merge Sorted Array (lab 01) is the same family with a twist. Two sorted lists. The first one has empty
space at its end. You must merge the second one into it.

If you fill from the front, you overwrite values in the first list before you've read them.

So fill from the **back**. The biggest values go at the end, and the end is empty space. Three pointers:
one at the last real item of list 1, one at the last item of list 2, one at the last slot overall.
Each step, take the bigger of the two, put it at the write slot, move left.

```
nums1 = [2, 5, 9, _, _]    nums2 = [3, 7]
               p1     w           p2
9 vs 7 → 9 is bigger → nums1[w] = 9
```

The question you must answer in your PLAN: **when list 1 runs out first, what's left to do? When list 2 runs out first?**

## Common mistakes in this family

- **Returning the list instead of `k`.** Read the signature. (M6)
- **`write + 1` without `=`.** (M4)
- **Comparing with the wrong neighbor** in Remove Duplicates. Trace `[1, 1, 1, 2]` to see it.
- **Building a new list** and assigning `nums = new_list`. That only renames locally. The grader's list is unchanged.
  If you must, `nums[:] = new_list` replaces the contents, but that uses O(n) space and misses the point.

## Pattern trigger

> **"In place," "return k," "first k elements," and a sorted input → read/write pointers.**
