## Counting is a superpower

Many array problems become easy once you count things. Count with a dict, or with `Counter`.
Then read the answer off the counts.

```python
from collections import Counter
counts = Counter([4, 1, 4, 4, 2])   # {4: 3, 1: 1, 2: 1}
```

O(n) time. O(k) space for k different values.

## Majority Element: three answers, three lessons

The problem (lab 05): one value appears **more than half** the time. Find it.

You will solve it at least two ways. Each teaches something.

### Way 1 — count everything

Count every value. Return the one whose count is over `n // 2`. O(n) time, O(n) space. This is the answer
you should reach first. It's correct and fast.

### Way 2 — sort

If one value fills more than half the list, where must it sit after sorting? Draw a few sorted lists and
mark the middle index. O(n log n) time. A one-liner. Good to *see*, not the best.

### Way 3 — the voting trick (Boyer–Moore)

The follow-up asks: can you do it in **O(1) space**? Here's the idea, told as a story.

> Picture a room. Everyone holds a sign with their value. Pair off two people with **different** signs and
> send both home. Keep doing it. Since the majority value has more than half the people, it can't be fully
> paired off. Whoever is left standing holds the majority sign.

In code you don't pair people. You keep one **candidate** and a **count**.

```
candidate = none, count = 0
for each value x:
    if count == 0: candidate = x        # room is empty; x takes the floor
    if x == candidate: count += 1       # an ally joins
    else: count -= 1                    # an opponent cancels one ally
```

Trace it on `[2, 2, 1, 1, 1, 2, 2]`:

| x | candidate | count |
|---|---|---|
| 2 | 2 | 1 |
| 2 | 2 | 2 |
| 1 | 2 | 1 |
| 1 | 2 | 0 |
| 1 | 1 | 1 |
| 2 | 1 | 0 |
| 2 | 2 | 1 |

Final candidate: 2. Correct.

This only works because a majority is **guaranteed**. Without that guarantee, you'd need a second pass to check.
Say that out loud in an interview. It shows you understand *why* it works.

## H-Index: sort, then read the picture

The problem (lab 06): a researcher's papers have citation counts. Their h-index is the largest `h` such that
they have at least `h` papers with at least `h` citations each.

Read that twice. Then do this: **sort the citations, biggest first, and draw them as bars.**

```
citations sorted high → low: [6, 5, 3, 1, 0]
paper #:                       1  2  3  4  5

paper 1 has 6 ≥ 1  ✓
paper 2 has 5 ≥ 2  ✓
paper 3 has 3 ≥ 3  ✓
paper 4 has 1 ≥ 4  ✗   → h = 3
```

The picture tells you the rule. Turn it into a loop. That's an O(n log n) answer, and it's a fine one.

**Stretch:** can you do it in O(n) with counting? Hint: no paper can push h above `n`. So a citation count
bigger than `n` can be treated as `n`. That means you can count into buckets 0..n.

## Common mistakes

- **Majority:** using `>= n // 2` instead of `> n // 2`. Check with n = 4.
- **Voting trick:** setting the candidate in the wrong order. The `count == 0` check comes **before** the compare.
- **H-Index:** confusing the paper's *position* with its *citation count*. That's M1 in disguise.
  The position (1-based) is the "h I'm testing." The value is the citations.

## Pattern triggers

> **"Appears more than n/2 times" → count it, or Boyer–Moore voting for O(1) space.**
> **A threshold defined by rank ("at least h items with at least h") → sort, then compare value to position.**
