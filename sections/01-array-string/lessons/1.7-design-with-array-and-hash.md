## A new kind of problem: build a class

Some problems don't give you a function. They give you a **class** to build. The grader creates one object,
then calls its methods many times.

```python
class Counter:
    def __init__(self):          # runs once, when the object is created
        self.total = 0           # self.total belongs to this object

    def add(self, x):            # every method gets self first
        self.total += x

    def get(self):
        return self.total

c = Counter()
c.add(5)
c.add(2)
c.get()   # 7
```

Rules you need:

- `__init__` sets up the data. Store everything on `self`.
- Every method's first parameter is `self`.
- Inside methods, use `self.something` to read or change the object's data.

## The problem

Build a set with three operations, each **O(1) on average**:

- `insert(val)` — add if missing. Return True if added.
- `remove(val)` — remove if present. Return True if removed.
- `getRandom()` — return a random element. Each element equally likely.

## Why one structure isn't enough

| Structure | insert | remove | getRandom |
|---|---|---|---|
| Python `set` | O(1) | O(1) | **O(n)** — no index, so you'd have to copy it to a list first |
| Python `list` | O(1) append | **O(n)** — must find it, then shift | O(1) — `random.choice` |

Each one fails at one thing. So use both.

- A **list** holds the values. That makes `getRandom` O(1).
- A **dict** maps each value to its **index in the list**. That makes "where is it?" O(1).

## The hard part: removing from the middle of a list in O(1)

Removing from the middle shifts everything after it. O(n).
Removing from the **end** is O(1).

So: **swap the item you want to remove with the last item. Then pop the end.**

```
list:  [10, 20, 30, 40]     dict: {10:0, 20:1, 30:2, 40:3}
remove 20

1. Where is 20?           dict[20] = 1
2. Last item is 40.       move 40 into slot 1 → list [10, 40, 30, 40]
3. Update 40's index.     dict[40] = 1
4. Pop the end.           list [10, 40, 30]
5. Delete 20 from dict.   dict {10:0, 30:2, 40:1}
```

Order matters. Write these five steps in your PLAN. Then trace the case where the item you remove **is** the
last item. Does your order still work?

## Common mistakes

- Forgetting to update the moved item's index in the dict. The set looks fine until a later remove breaks.
- Deleting from the dict before reading the index you need.
- Using `list.remove(val)` — that's O(n).
- Using `random.choice(set)` — that fails; sets don't support indexing.

## Pattern trigger

> **"O(1) insert, delete, AND random access / index" → list + dict of value → index; delete by swapping with the last element.**

You'll see the same "combine two structures so each covers the other's weakness" idea in LRU Cache (Section 08).
