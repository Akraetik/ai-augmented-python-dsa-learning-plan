## The idea: track how far you could get

In Jump Game (lab 10), each number says how far you *may* jump from that spot. Can you reach the end?

The brute force tries every jump from every spot. That explodes.

The better question: **standing here, what's the farthest index I could reach so far?**
Call it `reach`. Walk left to right. At each index, if you can stand there at all, update `reach`.

If you ever stand on an index that's **beyond** `reach`, you're stuck. You can't get there.

```
nums:   [2, 3, 1, 1, 4]
index:   0  1  2  3  4

i=0  reach = max(0, 0+2) = 2
i=1  1 <= 2, ok.  reach = max(2, 1+3) = 4   ← already reaches the end
```

```
nums:   [3, 2, 1, 0, 4]
i=0  reach = 3
i=1  reach = max(3, 3) = 3
i=2  reach = 3
i=3  reach = max(3, 3+0) = 3
i=4  4 > reach 3 → stuck. False.
```

The zero at index 3 is a wall. Every path lands on it, and it goes nowhere.

## Jump Game II: fewest jumps, counted in "levels"

Lab 11 promises you can reach the end. It asks: **what's the fewest jumps?**

Think of it like rings. With 0 jumps you can stand on index 0. With 1 jump you can stand anywhere from 1 up to
`nums[0]`. With 2 jumps, anywhere reachable from that first ring. And so on.

You walk through each ring and track the farthest point the **next** ring can reach. When you hit the end of the
current ring, you must jump. Count it. The next ring's farthest point becomes the new ring end.

```
nums:  [2, 3, 1, 1, 4]
ring 0: index 0                 farthest next = 2
ring 1: indexes 1..2            farthest next = max(1+3, 2+1) = 4  → reaches the end
answer: 2 jumps
```

You need three variables. Name them in your PLAN before you code: the jump count, where the current ring ends,
and the farthest the next ring reaches.

This is breadth-first search in disguise. You'll meet BFS for real in Section 10. Notice the shape now.

## Gas Station: a greedy proof you can feel

Lab 12. Gas stations sit in a circle. Each gives some gas and the drive to the next costs some gas.
Find the station where you can start and make it all the way around. There's at most one answer.

Two facts make this O(n).

**Fact 1.** If total gas is less than total cost, no start works. Return -1.

**Fact 2.** Say you start at station `s` and run dry trying to reach station `j`. Then **no station between
`s` and `j` can be the start either.** Why? You arrived at each of those stations with zero or more gas in the
tank. Starting fresh there means arriving with zero. Zero is never better. So you can skip straight to `j + 1`.

So: walk once. Keep a running tank. If it goes negative, the start must be after this point. Reset the tank
and move the start.

Write Fact 2 in your own words in your PLAN. If you can explain it, you can code it.

## Common mistakes

- **Jump Game:** checking `reach >= len(nums)` instead of `>= len(nums) - 1`. The last index is `len - 1`. (M5)
- **Jump Game II:** counting a jump when you're already at the last index. Loop to `len(nums) - 1`, not `len(nums)`.
- **Gas Station:** using O(n²) — try each start, simulate the whole loop. The perf test will catch it.

## Pattern triggers

> **"Can you reach the end?" → track farthest reach in one pass.**
> **"Minimum jumps / steps" with ranges → count levels (BFS-like) with a current-end and next-farthest.**
> **"Circular route, find the start" → total check + reset the start when the running sum goes negative.**
