## Strings are lists you can't change

Read them like lists: index, slice, loop. Build new ones with a list of pieces and `"".join(...)`.
That's the whole toolkit from Lesson 00.3. This lesson is about **how to think** about string problems.

## Skill 1 — walk from the end

Lab 17 asks for the length of the last word. Trailing spaces are allowed.

There's an easy way: `split()` handles all the spaces for you. Do that first. One line.

Then do it the interviewer's way: no `split`. Start at the end. Skip spaces. Count letters until the next space.
This trains backward loops, which you'll need again.

```python
i = len(s) - 1
while i >= 0 and s[i] == " ":    # skip trailing spaces
    i -= 1
```

Notice `i >= 0` comes **first** in the `and`. If `i` hits -1, Python checks `i >= 0`, sees False, and never
reads `s[-1]`. That's short-circuiting. It's how you guard an index.

## Skill 2 — compare column by column

Lab 18: the longest prefix shared by every string.

Think of the strings stacked as rows. Read **columns**, top to bottom, left to right.

```
f l o w e r
f l o w
f l i g h t
↑ ↑ ✗        stop at column 2
```

The outer loop is over **column positions**. The inner loop is over **strings**. Stop at the first column where
a string is too short or a letter differs. This is exactly where Mistake **M2** happens: looping over the wrong
thing. Say it before you code: "One pass of the outer loop = one character position."

## Skill 3 — split, reverse, join

Lab 19: reverse the order of words. Extra spaces anywhere. Output single-spaced.

`split()` with no argument already removes every extra space. Then reverse the list. Then join with `" "`.
That's a fine answer. Know why it handles the spaces.

The follow-up asks for an in-place version on a character array. In Python, strings are immutable, so you'd
convert to a list first. The trick is the same as Rotate Array: reverse everything, then reverse each word.

## Skill 4 — matching a pattern inside a string

Lab 20: find the first index where `needle` appears inside `haystack`.

The built-in `haystack.find(needle)` does it. Interviewers want to see you do it by hand.

Brute force: try each starting position. At each, compare character by character. Stop at the first mismatch.

```
haystack: s a d b u t s a d
needle:   s a d
          ↑ start 0: s=s, a=a, d=d → found at 0
```

Careful with the range of starting positions. If the haystack is length 9 and the needle is length 3,
the last possible start is index 6. Write that bound in your PLAN. (M5.)

That's O(n·m). Fine for this problem's limits. Faster methods (KMP, rolling hash) exist. You don't need them yet.

## Skill 5 — lookup tables

Labs 21 and 22: Roman numerals.

Put the symbol values in a dict. Don't use a chain of `if` statements.

```python
VALUE = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000}
```

**Roman → integer (lab 21).** Usually you add each value. The exception: a smaller value **before** a larger one
means subtract (IV = 4, IX = 9). So at each symbol, peek at the next one. If the next is bigger, subtract this one.
Watch the last symbol: there is no next. (M5.)

**Integer → Roman (lab 22).** Greedy. List every value a symbol (or special pair) can stand for, biggest first:
1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1. Take the biggest one that fits. Subtract. Repeat.
Including 900, 400, 90, 40, 9, 4 in the list is what makes greedy work here.

## Skill 6 — simulate, then look for the pattern

Lab 23: write a string in a zigzag across `numRows` rows, then read row by row.

```
numRows = 3, "PAYPALISHIRING"
P   A   H   N
A P L S I I G
Y   I   R
→ "PAHNAPLSIIGYIR"
```

Don't hunt for an index formula first. **Simulate.** Keep one list of characters per row. Walk the string.
Put each character in the current row. Move down. When you hit the bottom row, switch to moving up.
When you hit the top, switch back. Join the rows at the end.

Edge case: `numRows = 1`. There's nowhere to bounce. Return the string as-is. Your direction logic will
break without this check. Test it.

## Skill 7 — careful bookkeeping (Stretch)

Lab 24, Text Justification, is "hard" because of bookkeeping, not cleverness. Greedy: pack as many words as fit
on each line. Then spread the spaces. Extra spaces go to the **left** gaps first. The last line, and any line
with one word, is left-justified.

Break it into helper functions:

1. `pick_line(words, start, width)` → which words fit on this line?
2. `justify(line_words, width)` → the spaced-out string.
3. `left_justify(line_words, width)` → for the last line.

Use `divmod(total_spaces, gaps)` to get spaces-per-gap and how many gaps get one extra.

Write and test each helper alone. That's how you'd do it in a real job, too.

## Common mistakes in string problems

- Building with `+=` in a loop. Use a list and join.
- Off-by-one on the last start position in substring search. (M5)
- Looping over the wrong thing in column-wise comparisons. (M2)
- Forgetting the single-row / single-word edge cases.
- Peeking at `s[i + 1]` on the last character. (M5)

## Pattern triggers

> **"Last word," "trailing spaces" → walk backward and skip spaces, guard with `i >= 0` first.**
> **"Common prefix" → compare column by column, stop at first mismatch.**
> **Symbol ↔ value conversions → dict lookup table; greedy biggest-first for building.**
> **"Zigzag," "spiral," odd layouts → simulate with direction flags before hunting formulas.**
