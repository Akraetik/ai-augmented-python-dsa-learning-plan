## The idea

Many problems ask for "the best pair" where one item must come **before** the other.
The brute force checks every pair: O(n²).

The fast version walks once and remembers **the best thing seen so far** on the left.
At each step, it asks: "If this item is the second half of the pair, what's the best first half I've already seen?"

That's one remembered value instead of a whole inner loop. O(n).

## Worked example: the biggest jump forward

Not a lab. Same pattern.

> Given numbers in order, find the biggest `nums[j] - nums[i]` where `i < j`. If nothing goes up, return 0.

```python
def biggest_rise(nums: list[int]) -> int:
    lowest = float("inf")    # lowest value seen so far, to the left
    best = 0
    for x in nums:
        lowest = min(lowest, x)          # update what's behind us
        best = max(best, x - lowest)     # best pair ending HERE
    return best
```

Trace `[7, 2, 8, 1, 4]`:

| x | lowest | x − lowest | best |
|---|---|---|---|
| 7 | 7 | 0 | 0 |
| 2 | 2 | 0 | 0 |
| 8 | 2 | 6 | 6 |
| 1 | 1 | 0 | 6 |
| 4 | 1 | 3 | 6 |

Answer 6. Notice: when we hit 1, the lowest changes, but the best stays 6. The pair (2, 8) already happened.
That's why `best` and `lowest` are separate.

Look closely at the order of the two update lines. Does it matter here? Try swapping them and re-tracing.
(It doesn't change the answer here, because `x - x` is 0. In other problems order matters. Always think about it.)

**This worked example is lab 08 in disguise.** Prices are the numbers. Buy is `i`, sell is `j`.
Close this lesson, open the lab, and write it from memory. That's the point.

## Lab 09: many trades allowed

Now you may buy and sell as many times as you like, holding one share at a time.

Draw the prices as a line chart. Every upward slope is money. Every downward slope you'd rather skip.

```
price
  6 |         *
  5 |   *    / \
  4 |  / \  /   \
  3 | /   \/     *
  1 |*
     day 1 2 3 4 5 6
```

Here's the key question for your PLAN: **is grabbing every single up-step the same as grabbing whole climbs?**
A climb from 1 to 5 equals the step 1→3 plus the step 3→5. Try it with numbers.

If yes, the code is short. That's greedy: take every small gain, and the total is the best total.

## When greedy is safe

Greedy means: make the best local choice, never look back. It's not always right. It's right here because
taking one up-step never blocks you from taking another. Interviewers love asking "why is greedy correct here?"
Have a one-sentence answer ready for each greedy problem you solve.

## Common mistakes

- Starting `lowest` at 0. All prices are positive, so `lowest` never updates. Start at the first price or infinity.
- Returning a negative number when prices only fall. The problem wants 0. `best` should start at 0.
- In lab 09, trying to find "valleys and peaks" with complicated index logic. It works, but there's a two-line version.

## Pattern triggers

> **"Best pair where one must come before the other" → one pass, track best-so-far on the left.**
> **"Unlimited transactions" → add every positive day-to-day difference.**
