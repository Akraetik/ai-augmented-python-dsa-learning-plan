## Rotation in one picture

Rotate right by `k` means: each item moves `k` places to the right, and items that fall off the end wrap
around to the front.

```
[1, 2, 3, 4, 5, 6, 7]   rotate right by 3
[5, 6, 7, 1, 2, 3, 4]
```

## Tool 1 — modulo wraps an index

The item at index `i` moves to index `(i + k) % n`.

```
n = 7, k = 3
i = 0 → 3
i = 5 → 8 % 7 = 1
i = 6 → 9 % 7 = 2
```

`%` turns "past the end" into "back at the start." You'll see it in every circular problem.

Also: rotating by `n` puts everything back where it started. So rotating by `k` is the same as rotating by
`k % n`. **Always reduce `k` first.** If `k = 10` and `n = 7`, you only rotate by 3. Forgetting this breaks
the code when `k > n`.

## Tool 2 — the reversal trick

Rotating in place with O(1) space looks hard. There's a neat trick. Watch.

```
start:              [1, 2, 3, 4, 5, 6, 7]     k = 3
reverse all:        [7, 6, 5, 4, 3, 2, 1]
reverse first k:    [5, 6, 7, 4, 3, 2, 1]
reverse the rest:   [5, 6, 7, 1, 2, 3, 4]     done
```

Why does it work? Reversing everything puts the last `k` items at the front, but backward.
It puts the first `n − k` items at the back, also backward. Reversing each block fixes its order.

You already wrote "reverse in place" in Section 00 (lab 0.04). Here, write a helper that reverses
**between two indexes**: `reverse(nums, left, right)`. Then call it three times.

## Three ways to solve Rotate Array

| Way | Time | Space | Notes |
|---|---|---|---|
| Rotate by one, k times | O(n·k) | O(1) | Too slow when k is large |
| Copy into a new list at `(i + k) % n`, then copy back | O(n) | O(n) | Easy to get right. Good first answer. |
| Three reversals | O(n) | O(1) | The follow-up answer |

The lab's speed test will catch the first way. Do the second way first. Then the third.

## The in-place trap

```python
nums = nums[-k:] + nums[:-k]     # WRONG for in-place: only renames locally
nums[:] = nums[-k:] + nums[:-k]  # works: replaces contents. But O(n) extra space.
```

The first line is the most common wrong answer on this problem. It "works" when you print inside your function.
The caller's list never changes. Remember Lesson 00.3: functions can change a list, but `nums = ...` only
moves the local name.

## Worked example: a helper that reverses a section

```python
def reverse_section(nums, left, right):
    while left < right:
        nums[left], nums[right] = nums[right], nums[left]
        left += 1
        right -= 1
```

## Pattern triggers

> **"Circular," "wrap around," "rotate" → modulo: `(i + k) % n`, and reduce `k %= n` first.**
> **"Rotate in place, O(1) space" → three reversals.**
