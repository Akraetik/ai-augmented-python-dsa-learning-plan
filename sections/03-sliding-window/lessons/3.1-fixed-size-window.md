## The idea

A **window** is a run of items next to each other: `nums[left .. right]`.
Many problems ask about every window of one size `k`. The sum of each one. The letters in each one.

The slow way rebuilds each window from scratch:

```python
for start in range(n - k + 1):
    total = sum(nums[start:start + k])     # k steps, every time
```

That's O(n · k). At n = 100,000 and k = 50,000, it's billions of steps.

The fast way **slides** the window one step at a time. Each slide, one item enters on the right and one
item leaves on the left. Everything in the middle stays. So you only update for those two items.

```
nums: [2, 1, 5, 1, 3, 2]     k = 3

[2  1  5] 1  3  2            sum = 8
 2 [1  5  1] 3  2            8 + 1 − 2 = 7      (1 enters, 2 leaves)
 2  1 [5  1  3] 2            7 + 3 − 1 = 9      (3 enters, 1 leaves)
 2  1  5 [1  3  2]           9 + 2 − 5 = 6      (2 enters, 5 leaves)
```

Each slide is O(1). The whole scan is **O(n)**.

## Worked example: the biggest sum of any k items in a row

```python
def max_window_sum(nums, k):
    window = sum(nums[:k])          # build the first window once
    best = window
    for right in range(k, len(nums)):
        window += nums[right]       # enters
        window -= nums[right - k]   # leaves
        best = max(best, window)
    return best
```

Look at `right - k`. When `right` enters, the item `k` places behind it leaves. Trace it on the example
above and check that `right - k` names the right item each time. (Mistake **M5** lives in that index.)

Lab 01 is this worked example with one change: it wants the biggest **average**. Divide by `k` at the end.

## Fixed windows of counts (Permutation in String)

Lab 02: does `s2` contain some rearrangement of `s1` as a block of letters next to each other?

`s1 = "ab"`, `s2 = "eidbaooo"` → True, because `"ba"` sits inside `s2`.

A rearrangement has **the same letter counts**. So the question becomes: is there a window of length
`len(s1)` in `s2` whose letter counts match `s1`'s?

Same slide, but the window holds **counts** instead of a sum:

```
s1 counts: {a: 1, b: 1}        window size 2

e i d b a o o o
[e i]                   {e:1, i:1}         no
  [i d]                 {i:1, d:1}         no
    [d b]               {d:1, b:1}         no
      [b a]             {b:1, a:1}         match → True
```

Each slide: add one to the entering letter, subtract one from the leaving letter. Then compare.

Comparing two Counters costs O(26) for lowercase letters. That's a constant, so the scan is still O(n).

One cleanup detail: when a count drops to 0, delete the key (or use a 26-slot list). Otherwise
`Counter({'a': 1, 'b': 0}) == Counter({'a': 1})` can trip you up. (Python 3.10+ treats them as equal, but
older versions and hand-written dicts don't. A 26-slot list avoids the question entirely.)

## Pattern trigger

> **"Every window of size k," "k consecutive," "a block the same length as X" → fixed window: add the entering item, remove the leaving item.**
