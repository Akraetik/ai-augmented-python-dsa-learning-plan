## When the size isn't fixed

Now the problem asks for the **longest** run that follows some rule:

- longest substring with no repeated letter
- longest run of 1s if you may flip up to `k` zeros
- longest block you can make all one letter with `k` changes

The window size changes as you go. So both edges move, at different times.

## The template

```python
left = 0
best = 0
for right in range(len(s)):
    # 1. GROW: add s[right] to the window
    while WINDOW_IS_BROKEN:
        # 2. SHRINK: remove s[left] from the window
        left += 1
    # 3. RECORD: the window is valid again
    best = max(best, right - left + 1)
return best
```

Three steps, in that order, every time.

1. **Grow.** `right` takes one step. The new item joins.
2. **Shrink.** While the window breaks the rule, drop items from the left.
3. **Record.** Now the window is valid. Its length is `right - left + 1`.

**`right - left + 1`, not `right - left`.** A window from index 2 to index 5 holds 4 items: 2, 3, 4, 5.
Mixing these up is Mistake **M5**.

**`while`, not `if`.** One step left may not fix the window. Keep shrinking until it's valid.

## Why it's O(n), even with a loop inside a loop

The `while` sits inside the `for`. It looks like O(n²). It isn't.

`left` only moves forward. It never jumps back. Over the whole run, `left` moves at most `n` times in total,
and `right` moves exactly `n` times. So the total work is at most `2n`. **O(n).**

This is called **amortized** analysis: some steps are expensive, but the total is bounded.
Interviewers often ask "isn't that O(n²)?" Have this answer ready.

## Longest Substring Without Repeating Characters (lab 03)

The rule: no letter appears twice in the window. Keep a **set** of letters in the window.

```
s = "abcabcbb"

right  letter  window      action                      best
  0      a     a                                         1
  1      b     ab                                        2
  2      c     abc                                       3
  3      a     abca        'a' repeats → drop 'a'
                bca                                      3
  4      b     bcab        'b' repeats → drop 'b'
                cab                                      3
```

Grow: add `s[right]`. Broken when: `s[right]` was already in the set. Shrink: remove `s[left]` from the set,
then `left += 1`, until the duplicate is gone.

Careful with the order. Check for the duplicate **before** you add the new letter, or count letters with a
dict and shrink while the new letter's count is above 1. Both work. Pick one and trace `"dvdf"` with it.
(The answer is 3: `"vdf"`.)

**A faster jump.** With a dict of `letter → last index seen`, you can jump `left` straight past the old copy:
`left = max(left, last[ch] + 1)`. The `max` matters: `left` must never move backward. Trace `"abba"` to see why.

## Max Consecutive Ones III (lab 04)

The list holds 0s and 1s. You may flip up to `k` zeros. Longest run of 1s?

Restate it: **the longest window with at most `k` zeros in it.** You never actually flip anything.

Keep a count of zeros in the window. Grow: if the new item is 0, add one. Broken when: zeros > k.
Shrink: if `nums[left]` is 0, subtract one, then `left += 1`.

You wrote the 0-flip-free version in Section 00 (lab 0.07). This one adds the shrink step.

## Longest Repeating Character Replacement (lab 05)

You may change up to `k` letters. What's the longest block you can make all one letter?

In any window, the best plan is to keep the **most common** letter and change all the others.
The number of changes needed is:

```
changes = window length − count of the most common letter
```

Broken when: `changes > k`.

Keep a 26-slot count list (or a dict). After each grow, the most common count is `max(counts)`. That's
26 steps, a constant. So the scan stays O(n).

There's a famous shortcut where you never decrease the stored max. It works, but the reason is subtle.
Get the simple version working first. The solution file explains the shortcut.

## Pattern trigger

> **"Longest run / substring / subarray that follows a rule" → variable window: grow right, shrink left while broken, record after the while.**
