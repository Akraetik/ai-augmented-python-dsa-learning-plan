## A grid is a list of rows

```python
grid = [
    [1, 2, 3],     # row 0
    [4, 5, 6],     # row 1
]
```

- `grid[r]` is a whole row. `grid[r][c]` is one cell: **row first, then column.**
- Rows: `len(grid)`. Columns: `len(grid[0])`.
- Interview code usually names them `m` (rows) and `n` (columns), or `rows` and `cols`.

```
           c=0  c=1  c=2
   r=0  [  1    2    3  ]
   r=1  [  4    5    6  ]

grid[1][2] → 6        2 rows, 3 columns
```

Think "row, column" like "down, across." Swapping them is Mistake **M1** wearing a new hat:
`grid[c][r]` reads the wrong cell, or crashes when the grid isn't square.

## Walking every cell

```python
rows, cols = len(grid), len(grid[0])
for r in range(rows):
    for c in range(cols):
        ...                      # grid[r][c]
```

Two loops, but it's still one visit per cell: **O(m · n)**. That's linear in the size of the grid.
For a grid problem, O(m · n) is usually the best you can do, because you must look at every cell once.

## Building a new grid (the trap from Section 00)

```python
bad  = [[0] * cols] * rows               # every row is the SAME list
good = [[0] * cols for _ in range(rows)] # each row is its own list
```

Change `bad[0][0]` and every row changes. Always use the comprehension.

## Neighbors and the bounds check

Many grid problems look at the cells around one cell. Keep the moves in a list:

```python
FOUR  = [(-1, 0), (1, 0), (0, -1), (0, 1)]                  # up, down, left, right
EIGHT = FOUR + [(-1, -1), (-1, 1), (1, -1), (1, 1)]         # plus the diagonals

for dr, dc in EIGHT:
    nr, nc = r + dr, c + dc
    if 0 <= nr < rows and 0 <= nc < cols:     # stay inside the grid
        ...
```

The bounds check comes **before** you read `grid[nr][nc]`. Python treats `grid[-1]` as the last row,
so a missing check doesn't always crash. It quietly reads the wrong cell. That's worse.

## Transpose (lab 01)

Transpose flips the grid over its main diagonal. Row `r`, column `c` moves to row `c`, column `r`.
A 2 × 3 grid becomes 3 × 2.

```
[1 2 3]       [1 4]
[4 5 6]   →   [2 5]
              [3 6]
```

Build a new grid of the new shape, then copy `out[c][r] = grid[r][c]`.
Python's one-liner: `[list(row) for row in zip(*grid)]`. Know both. Explain the loop version.

## Diagonals (lab 02)

In a square `n × n` grid:

- **main diagonal:** `r == c` → cells `(0,0), (1,1), (2,2)...`
- **anti-diagonal:** `r + c == n - 1` → cells `(0,n−1), (1,n−2)...`

You don't need two loops to visit a diagonal. One loop over `i` gives `(i, i)` and `(i, n − 1 − i)`.
That's O(n), not O(n²). When `n` is odd, both diagonals share the center cell. Count it once.

## Pattern trigger

> **Any 2D grid → `grid[r][c]`, rows = len(grid), cols = len(grid[0]); a directions list plus a bounds check for neighbors.**
