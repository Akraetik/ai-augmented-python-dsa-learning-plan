## The idea

Put one pointer at the **start** and one at the **end**. Look at the two items. Decide which pointer moves
inward. Stop when they meet.

```
 [ a  b  c  d  e  f ]
   ↑              ↑
  left          right       → compare, then move one (or both) inward
```

Every step removes at least one item from consideration. So the loop runs at most n times: **O(n) time,
O(1) space.** That's the whole appeal. You already used it to reverse a list in Section 00 (lab 0.04).

The skeleton:

```python
left, right = 0, len(items) - 1
while left < right:
    # look at items[left] and items[right]
    # decide: move left, move right, or both
```

The hard part is never the loop. It's the **decision**: which pointer moves, and why that's safe.

## Use 1 — symmetry checks (Valid Palindrome)

A palindrome reads the same forward and backward. So the first character must equal the last, the second
must equal the second-to-last, and so on. Two pointers check exactly those pairs.

Lab 01 adds a twist: ignore anything that isn't a letter or digit, and ignore case.
`"A man, a plan, a canal: Panama"` is a palindrome.

You could build a cleaned copy first: `cleaned = [c.lower() for c in s if c.isalnum()]`, then compare it
with its reverse. That's O(n) time and O(n) space. Fine as a first answer.

The two-pointer version skips junk **in place**:

```
 "A, b a"
  ↑     ↑      'A' vs 'a' → equal (ignoring case), both move
     ↑  ↑      ',' isn't alphanumeric → skip it, left moves
       ↑↑ ... 
```

When you skip, use an inner `while` that also checks `left < right`. Otherwise a string of all punctuation
runs `left` off the end. (Mistake **M5**.)

## Use 2 — sorted pairs (Two Sum II)

Lab 03: the list is **sorted**. Find two numbers that add to `target`. Return their positions, **1-indexed**.

Here's the move that makes two pointers work on sorted data:

```
numbers = [2, 7, 11, 15], target = 18
           L          R     2 + 15 = 17  → too small. Which pointer can make the sum BIGGER?
              L       R     7 + 15 = 22  → too big.   Which pointer can make the sum SMALLER?
              L   R         7 + 11 = 18  → found.     Return [2, 3] (1-indexed!)
```

- Sum too small → move `left` right (the only way to get a bigger number).
- Sum too big → move `right` left (the only way to get a smaller number).

**Why is it safe to throw away `numbers[left]` when the sum is too small?** Because `numbers[right]` is the
biggest number still in play. If even the biggest partner can't reach the target, `numbers[left]` has no
partner at all. It's done. That one sentence is the proof. Say it in interviews.

You solved Two Sum in Section 00 with a dict. That works here too, but uses O(n) space. The problem wants
O(1) extra space. The sorted order is the hint.

## Use 3 — fill from the biggest end (Squares of a Sorted Array)

Lab 04: the list is sorted, but may contain negatives. Return the squares, sorted.

`[-4, -1, 0, 3, 10]` → squares `[16, 1, 0, 9, 100]` → sorted `[0, 1, 9, 16, 100]`.

The easy answer: square everything, then `sorted()`. O(n log n). Correct.

The O(n) answer: **where are the biggest squares?** At the two ends. The most negative number and the most
positive number. So the two pointers compare `abs(left)` vs `abs(right)`, take the bigger square, and write it
into the **last** open slot of the output. Fill from the back. Same idea as Merge Sorted Array (lesson 1.1).

## The three questions to ask

For any opposite-ends problem, write these in your PLAN:

1. What do I compare at `left` and `right`?
2. In each case, which pointer moves, and **why can I safely discard that item?**
3. When do I stop: `left < right` or `left <= right`? (Trace a 1-item and 2-item input. M5.)

## Pattern trigger

> **Sorted input + pair condition, or symmetry ("reads the same both ways") → pointers at both ends, walk inward.**
