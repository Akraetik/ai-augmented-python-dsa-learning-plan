# 2.4 · Sort First, Then Two Pointers (3Sum)

**Labs:** 06 3Sum · 08 3Sum Closest
**Time:** 50 minutes, then the labs. 3Sum is one of the most-asked medium problems. Take it slowly.

---

## The problem

Lab 06: find every **unique** triple of values `[a, b, c]` in `nums` with `a + b + c == 0`.
No duplicate triples in the answer.

`[-1, 0, 1, 2, -1, -4]` → `[[-1, -1, 2], [-1, 0, 1]]`

## Brute force

Three nested loops: O(n³). At n = 3,000, that's 4.5 billion triples. Plus you'd need a set of sorted tuples
to remove duplicates.

## Turn three into "one + two"

Fix the first number. Now you need two numbers that add to `-first`. That's **Two Sum II**, which you just
solved in O(n) on a sorted list.

So: **sort the list once.** Then, for each index `i`, run the two-pointer Two Sum on the part to its right.

```
sorted: [-4, -1, -1, 0, 1, 2]
          i   L            R      need -(-4) = 4:   -1 + 2 = 1 too small → L moves ...
              i   L        R      need 1:           -1 + 2 = 1 → found [-1, -1, 2]
```

Cost: sorting O(n log n), plus n runs of an O(n) scan → **O(n²)** total. That's the best known for this problem.

## The hard part: no duplicate triples

Sorted order puts equal values next to each other. That lets you skip repeats in three places:

1. **The fixed number.** If `nums[i] == nums[i - 1]`, you already found every triple starting with that value.
   Skip it. (Check `i > 0` first. M5.)
2. **After a match, the left pointer.** Move `left` forward past every copy of the value you just used.
3. **After a match, the right pointer.** Same, moving `right` back.

```
[-2, 0, 0, 2, 2]
  i  L        R     -2 + 0 + 2 = 0 → record [-2, 0, 2]
                    now skip: L moves past both 0s, R moves past both 2s
```

Without step 2 and 3 you'd record `[-2, 0, 2]` twice.

**Why skip `nums[i] == nums[i - 1]` and not `nums[i] == nums[i + 1]`?** The second version skips the *first*
copy and keeps the last. Then a triple like `[-1, -1, 2]` is lost, because the first `-1` never gets to pair
with the second. Trace `[-1, -1, 2]` both ways to see it.

## An early exit

The list is sorted. If `nums[i] > 0`, every number to its right is positive too. No triple can sum to 0.
Break out of the loop.

## 3Sum Closest (lab 08)

Same shape. Instead of "sum equals 0," track the sum **closest** to `target`. At each step:

- Update `best` if `abs(total - target)` is smaller.
- If `total < target`, move `left`. If bigger, move `right`. If equal, return it immediately.

No duplicate-skipping needed. Only one number is returned.

## Pattern trigger

> **"Find k numbers that sum to X" (k ≥ 3) → sort, fix the first k − 2 with loops, two-pointer the last two. Skip equal neighbors to avoid duplicates.**
