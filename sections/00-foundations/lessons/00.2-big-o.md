# 00.2 · Big-O: How Fast Is Your Code?

**Time:** 45 minutes. **Goal:** look at code and say its Big-O. Look at constraints and know what Big-O you need.

---

## The one idea

Big-O answers one question: **when the input gets bigger, how much more work does the code do?**

It doesn't measure seconds. Seconds depend on the computer. Big-O measures *growth*.

`n` means "the size of the input." For a list, `n` is its length. For a string, its number of characters.

## Count the loops

Most of the time you can find Big-O by looking at loops.

```python
def total(nums):
    s = 0
    for x in nums:        # runs n times
        s += x            # 1 step each time
    return s
```

One loop over `n` items. **O(n)**. "Linear." Double the input, double the work.

```python
def has_pair_sum(nums, target):
    for i in range(len(nums)):              # n times
        for j in range(i + 1, len(nums)):   # up to n times, for EACH i
            if nums[i] + nums[j] == target:
                return True
    return False
```

A loop inside a loop. About `n × n` steps. **O(n²)**. "Quadratic." Double the input, four times the work.

```python
def first(nums):
    return nums[0]
```

No loop. Same work for 10 items or 10 million. **O(1)**. "Constant."

## Loops in a row add. Loops inside loops multiply.

```python
for x in nums:       # n
    ...
for y in nums:       # n
    ...
```

`n + n = 2n`. We drop the 2. **O(n)**.

```python
for x in nums:           # n
    for y in nums:       # × n
        ...
```

`n × n`. **O(n²)**.

## Drop constants and small terms

Big-O only cares about the biggest term, as `n` gets huge.

| You counted | Big-O |
|---|---|
| `3n + 5` | O(n) |
| `n² + n` | O(n²) |
| `500` | O(1) |
| `n/2` | O(n) |

## The halving loop: O(log n)

```python
def count_halvings(n):
    steps = 0
    while n > 1:
        n = n // 2
        steps += 1
    return steps
```

Each pass cuts `n` in half. For `n = 1,000,000`, that's only about 20 passes.
**O(log n)**. "Logarithmic." Binary search works this way.

Rule of thumb: **if the problem gets cut in half each step, think log n.**

## The ladder

From fastest to slowest. Memorize this order. It's an Anki card.

| Big-O | Name | n = 100,000 means about... | Typical source |
|---|---|---|---|
| O(1) | constant | 1 step | index a list, look up a dict key |
| O(log n) | logarithmic | 17 steps | binary search |
| O(n) | linear | 100,000 steps | one loop |
| O(n log n) | "n log n" | 1.7 million steps | sorting |
| O(n²) | quadratic | 10 billion steps | loop in a loop |
| O(2ⁿ) | exponential | never finishes | trying every subset |

Python does roughly **10 to 50 million simple steps per second.**
So O(n²) on 100,000 items is minutes. The grader gives you about a second.

## Read the constraints, know your target

This table is the most useful thing in this lesson. Look at the largest `n` in the constraints.

| Largest n | Target Big-O | Usually means |
|---|---|---|
| ≤ 20 | O(2ⁿ) is fine | try everything (backtracking) |
| ≤ 1,000 | O(n²) is fine | a nested loop is OK |
| ≤ 100,000 (10⁵) | O(n log n) or O(n) | sort, or one pass with a dict/set |
| ≤ 10,000,000 (10⁷) | O(n) | one pass, no sorting |
| ≥ 10⁹ | O(log n) or O(1) | math or binary search |

When you see `1 <= nums.length <= 10^5`, you know a nested loop won't pass. Before you write a line.

## Hidden loops in Python

Some single lines of Python are secretly loops. This is where most "too slow" failures come from.

| Code | Cost | Why |
|---|---|---|
| `x in my_list` | **O(n)** | checks every item |
| `x in my_set` or `x in my_dict` | O(1) | jumps straight to it |
| `my_list.index(x)` | **O(n)** | searches |
| `my_list.pop()` | O(1) | removes from the end |
| `my_list.pop(0)` | **O(n)** | shifts everything left |
| `my_list.insert(0, x)` | **O(n)** | shifts everything right |
| `my_list.append(x)` | O(1)* | *on average |
| `my_list[a:b]` (slice) | **O(b − a)** | makes a copy |
| `sum(my_list)`, `max(...)`, `min(...)` | **O(n)** | each scans the whole list |
| `len(my_list)` | O(1) | Python stores the length |
| `sorted(my_list)` | **O(n log n)** | |
| `s1 + s2` (strings) | **O(len)** | makes a new string |
| `"".join(pieces)` | O(total length) | the right way to build a string |

The trap looks like this:

```python
for i in range(len(nums)):
    if nums[i] in nums[i+1:]:   # slice copies O(n), `in` scans O(n)
        return True
```

It looks like one loop. It's O(n²). Use a set.

## Space complexity

Space Big-O asks: **how much extra memory does the code use as input grows?**

- A few variables: **O(1)** space.
- A new list or dict that grows with the input: **O(n)** space.
- The input itself doesn't count.

"In place" problems want O(1) extra space. That means: change the given list, don't build a new one.

## Worked example

```python
def common(a, b):
    seen = set(a)              # O(len a) time, O(len a) space
    out = []
    for x in b:                # O(len b)
        if x in seen:          # O(1)
            out.append(x)
    return out
```

Time: **O(a + b)**. Two inputs, so we name both sizes. Space: **O(a)** for the set (plus the output).

## Trace it

Say the Big-O for each. Answers below. Then do `labs/lab_01_bigo_spotter.py`.

```python
# A
for i in range(n):
    for j in range(10):
        ...

# B
i = 1
while i < n:
    i *= 2

# C
nums.sort()
for x in nums:
    ...

# D
for x in nums:
    if x in nums:
        ...
```

<details><summary>Answers</summary>

- **A: O(n).** The inner loop is always 10. That's a constant.
- **B: O(log n).** `i` doubles each pass.
- **C: O(n log n).** Sort is n log n. The loop after it is n. The bigger one wins.
- **D: O(n²).** `x in nums` on a *list* is a hidden loop.
</details>
