# 00-1 How This Works

N: The AI-Augmented Python DSA Learning Plan. Section zero, track one. How this works.
N: This track is for the road. You don't need a screen. You don't need to take notes. Just listen.
[pause 1]
N: Here is the goal. You want to pass the coding part of a software engineering interview. In Python.
N: That part comes in two forms. The first is an online assessment. A timed test. LeetCode, Codility, HackerRank. Nobody watches you. A machine grades you.
N: The second is a live round. A person watches you solve a problem. They ask questions while you work.
N: This course trains for both.
[pause 1]
N: Let's start with the machine. What does it grade?
N: Two things. Correctness, and performance.
N: Correctness means your function gives the right answer. On every input. Not just the examples you can see. The grader runs hidden tests. An empty list. A list with one item. All the same number. Negative numbers. And the biggest input the problem allows.
N: Performance means your code is fast enough on that biggest input. Often a hundred thousand items or more.
N: Here's the trap. Most beginners only practice correctness. They write code that works on the small examples. Then the big hidden test runs, and it times out.
N: Codility is blunt about this. It gives you two scores. One for correctness. One for performance. A slow answer can get a hundred on the first and a zero on the second.
N: So every lab in this course runs a big input with a timer. You'll see the word SLOW when your code is correct but too slow. That's a real failure. Treat it like one.
[pause 1]
N: Next. Return, don't print.
N: The grader calls your function and looks at what comes back. It doesn't read your screen.
N: If you print the answer, the function gives back nothing. In Python, nothing is called None. The grader sees None, and marks you wrong.
N: Some problems say: change the list in place, and return nothing. Then you edit the list you were given. The grader checks that list after your function finishes.
N: How do you know which one you need? Read the function signature. The little arrow at the end of the first line tells you what comes back. If it says None, you change the input in place.
N: This is mistake M six in your log. Not reading the return type. The fix is simple. Before you plan anything, write down: returns, and then what it returns.
[pause 1]
N: Now the live round. A person watches. What are they grading?
N: Four things. Communication. Problem solving. Code quality. And testing.
N: Communication means you talk while you think. You restate the problem. You ask what happens with an empty input. You say, the simple way is this, and it's too slow because of that.
N: Problem solving means you find something that works, then you make it better.
N: Code quality means clean Python. Good variable names.
N: Testing means you walk through your own code with a small example. Out loud. And you catch your own bugs before they do.
N: In twenty twenty six, big companies still run these rounds with AI turned off. Many also run a debug round. They hand you broken code and watch you fix it. That's why each section has a Bug Hunt lab.
[pause 1]
N: Now, how this course works.
N: Each section follows the same eight steps.
N: One. Prime. You listen to the audio primer before you read anything. Like this track. It plants the words in your head so the reading goes faster.
N: Two. Learn. You read the lesson with your editor open. You type every example. Typing matters. Your fingers need the reps.
N: Three. Build. You do the labs. They come in tiers. Core is easy. Build is medium. Stretch is hard. Plus one Bug Hunt.
N: Four. Drill. Flashcards in Anki. Every day. Five to twenty minutes. On breaks.
N: Five. Explain. A question and answer session with Claude. You explain. It asks why. It catches fuzzy thinking.
N: Six. Test. A short quiz that scores you by topic. It tells you where you're weak.
N: Seven. Repair. You fix the weak spots. You log any mistake you've made twice. It becomes a flashcard.
N: Eight. Gate. Two days later, you solve problems from a blank file. Timed. No notes. Pass, and you move on.
[pause 1]
N: Why so many steps? Because of how memory works.
N: Reading something feels like learning. It mostly isn't. What builds memory is pulling the answer out of your own head. That's called retrieval practice. Flashcards, quizzes, and blank-file solves are all retrieval.
N: Spacing helps too. Short sessions over many days beat one long session. Anki handles the spacing for you.
N: And mixing helps. When problems are mixed up, you learn to pick the right tool. Not just use the tool the chapter told you to use.
N: One more. When a problem is hard, struggle a little before you look for help. Not forever. About fifteen minutes on an easy one. Then open one hint. Just one.
[pause 1]
N: Let's talk about the hint ladder.
N: Every problem has three hints. Hint one asks you a question. Hint two names the pattern. Hint three gives you pseudocode.
N: Open them one at a time. Try for ten more minutes after each one.
N: If you needed hint three, mark the problem as assisted. It comes back later for a cold solve.
N: Full solutions live in a separate folder. Open them after you solve the problem. Or after a real fight. Never before.
[pause 1]
N: Last thing. The problem routine. You'll hear this many times. Here it is once, slowly.
N: Restate the problem in your own words. And say what it returns.
N: Work one example by hand. On paper.
N: List the edge cases. Empty. One item. All the same. Negatives. Huge.
N: Say the brute force, and say how slow it is.
N: Find the pattern that cuts out the repeated work.
N: Then code it.
N: Then test it. By tracing. Line by line. Before you hit run.
[pause 1]
N: That's the whole system. Next track, Big O. How to tell if your code is fast enough, before you ever run it.
